# Website review — 24 October 2026

## Scope

Reviewed all public pages (home, about, contact/general and quote, catalogue, product detail and missing URLs), all admin pages (dashboard, product list/add/edit, categories, enquiries, staff, settings), and logged-out access protection.

Browser checks used headless Chrome at 1440 × 1000 and 390 × 844. The final run covered 37 page/viewport combinations, including a separate guest login check. Screenshots and machine-readable results are in ignored `artifacts/browser-review/`. Browser checks use a temporary Supabase sign-in session and sign it out afterward. They do not send emails or save/delete product or enquiry records.

## Corrections

- Removed the narrow dashboard frame and automatic dark-mode override, retaining the approved light content, navy navigation and burgundy controls. Removed the desktop sidebar logo as requested.
- Corrected legacy `.row` gap and alignment rules that overrode Bootstrap: summary cards now stay on one desktop row, dashboard side panels and settings columns align properly, and mobile cards form two columns.
- Fixed the product editor's Bootstrap specificity conflict. The live preview is beside the form on the right at desktop sizes and below the form on phones. Checked actual browser coordinates, rather than relying only on JSX tests.
- Verified preview updates and public/internal price handling. Added invalid photo type/size feedback before submission and required a price when public pricing is selected. Kept server-side image validation and rollback.
- Restored the existing product catalogue at `/admin/products`, added search, and provided confirmed product deletion from list and editor. Verified cancellation sends no mutation request.
- Added pending states to admin submit buttons to reduce duplicate submissions.
- Added enquiry pagination (50 per page), retained status/page filters after saves, and formatted enquiry timestamps in Sri Lanka time.
- Made invalid admin product IDs return a proper not-found result instead of a database error.
- Added route-specific error recovery and not-found boundaries, corrected duplicated landmarks on missing products, and added root metadata so unknown URLs have a browser title.
- Made the overflowing staff table keyboard-focusable on mobile.
- Corrected enquiry validation: required fields focus the first invalid input, short contact entries and non-positive quantities receive feedback, company length is bounded, and non-JSON server errors have a useful message.
- Corrected the enquiry dialog's initial scroll lock for direct `#enquire` links.
- Removed redundant sequential catalogue reads and tightened numeric query parsing.
- Shortened the intro to 1.2 seconds plus fade, limited it to the home page once per session, and skipped it for reduced-motion users. Admin pages and error recovery are no longer blocked by the intro.
- Updated email configuration display and status contrast while keeping passwords hidden.
- Forwarded refreshed authentication cookies into the current page request. Added a regression test for this behavior.
- Updated Next.js to 16.4.3 and Nodemailer to 10.2.1. npm reported zero known vulnerabilities after updates.
- Retired the old SQLite-only test suite as `tests/backend.sqlite-legacy.mjs`; it is reference material and no longer runs against the Supabase backend. Added current enquiry API, pagination, redirect and session tests instead.

## Still required before launch

- Select hosting, configure its private Supabase/SMTP environment variables and correctly configure the trusted proxy. The local `TRUST_PROXY=false` intentionally prevents production rate-limited login/enquiry operations until hosting is configured.
- Connect the purchased domain and HTTPS; set the Supabase Auth site URL and disable public signup for this staff-only administration flow.
- Remove the initial `ADMIN_PASSWORD` setting after account setup and use the admin change-password flow for future changes.
- Supply real photos for products currently showing the intentional “Photo coming soon” fallback. No substitute product photography was invented.
- Perform a disposable product create/upload/edit/delete and a real email-delivery test on a staging project. This review intentionally avoided live database mutations and sending messages.
- Customer confirmation emails are not implemented; notifications currently go to the configured team mailbox only.
- Changes have not been pushed or deployed during this review.

## Repeating the checks

```powershell
npm test
npm run format:check
npm run build
npm run test:browser
```

The browser review needs Google Chrome installed and your local Supabase server/publishable settings. Keep its output private because screenshots of the admin pages may contain customer names or contact information. It creates an authentication session but does not reset any password or send a sign-in email.
